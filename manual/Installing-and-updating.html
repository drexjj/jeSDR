Installing and updating#

jeSDR runs on the sBitx's Raspberry Pi 4 or Raspberry Pi 5 under Raspberry Pi OS 64-bit (Bookworm or later). On a Pi 5 the Pi needs a 5 V supply that can give 5 A. jeSDR drives the GPIO through the kernel's GPIO device, so no GPIO library (WiringPi) is needed; SPI must stay off (dtparam=spi=on in config.txt takes the pins the filters and the volume knob use). The SD card image is made on a Pi 4: on a Pi 5, run the one-line installer once after the first start. Nothing else may use the audio codec or the GPIO at the same time, so remove any other radio program from the desktop autostart.

SD card image#

  1. Download jesdr-<version>-sdcard.img.xz.
  2. Write it to a microSD card (16 GB or more) with Raspberry Pi Imager (Use custom) or balenaEtcher.
  3. Put the card in the radio and switch on. The first start takes a little longer: the card is expanded, and the radio makes its own HTTPS certificate and SSH keys.
  4. Open jeSDR from the desktop icon or the menu.

To put the card in the radio see Opening the case; to write a new card without opening it, or to copy or back up the whole card, see SD card images and backups.

Writing an image erases the card. Your settings, log and voice messages are in ~/jeSDR/data: make a backup first, or update with the button instead (below), which keeps them.

One-line installer#

On the radio, in a terminal:

curl -fsSL https://drexjj.github.io/jeSDR/install.sh | sudo bash

It checks the system, installs what jeSDR needs (including PipeWire and its development files, libpipewire-0.3-dev, so jeSDR can also be built on the Pi), sets up the WM8731 codec if it is not set up yet (other programs use jeSDR's own PipeWire audio devices; no loopback cards), downloads the latest package, checks its SHA-256 and installs it, then downloads the country file. It then offers to install JS8Call (JS8Call-improved's ARM64 AppImage, a separate GPL program, about 100 MB) for the JS8 mode; run it again later to add or update JS8Call. If it changed the audio set-up it offers to reboot.

Options go after bash -s --, for example | sudo bash -s -- --yes:

OptionDoes
--yesanswers yes to every question
--deb FILEinstalls this package instead of downloading the latest
--user NAMEruns jeSDR as this user (default: the user who ran sudo)
--no-hwleaves the codec and I²C set-up alone
--no-js8calldoes not offer JS8Call

Package#

sudo apt install ./jesdr_<version>_arm64.deb

It installs to /opt/jeSDR and runs as the service jesdr under the first normal user (or the user named in /etc/jeSDR/user).

Opening the radio's screen#

  • On the radio: the jeSDR desktop shortcut or the menu entry (Internet / Ham Radio) opens the radio in its own Chromium window.
  • From another device: open https://<radio>:8443/. The first time, the browser warns about the certificate (the radio makes its own); choose Advanced → Proceed, once per device. http://<radio>:8080/ redirects there. HTTPS is what lets a phone or laptop use its own microphone (Transmit).

  • Full screen on the radio (kiosk): add an autostart entry that runs /opt/jeSDR/jesdr-app --kiosk, for example in ~/.config/autostart/jesdr-kiosk.desktop:

    [Desktop Entry]
Type=Application
Name=jeSDR kiosk
Exec=/opt/jeSDR/jesdr-app --kiosk

    Press Alt+F4 to leave kiosk mode.

Every open browser shows the same radio.

Remote desktop (VNC)#

To operate the radio, a browser on the other device is better than a remote desktop: the radio sends only the data and the other device draws it. For the Pi's desktop itself (other programs, settings), turn on VNC in the Raspberry Pi menu → Preferences → Raspberry Pi Configuration → Interfaces → VNC, then connect with a VNC viewer (for example RealVNC Viewer) to the radio's address or <hostname>.local and sign in with the Pi's user name and password. The moving waterfall keeps VNC busy, so close the viewer when you're done (Troubleshooting).

Updates#

More → About → Software updates → Check now, then Install. The radio also looks once a day by itself (Check for updates daily, UPDATECHK) and says when there is a new version. Settings, log, calibration and voice messages are kept.

Updates are signed: the radio installs only a package whose manifest carries the jeSDR release signature and whose SHA-256 matches. If a new version does not start within a minute, the previous one is put back.

By hand: sudo apt install ./jesdr_<version>_arm64.deb.

Kernel I2C and the clock#

The radio's oscillator, SWR bridge, power monitor and real-time clock (RTC) share two GPIO pins. The Linux kernel drives that bus, with this line in /boot/firmware/config.txt (the sBitx image's own line):

dtoverlay=i2c-rtc-gpio,ds1307,i2c_gpio_sda=13,i2c_gpio_scl=6

It makes the bus and binds the clock on it. Only one overlay may use those pins: with a second one (such as dtoverlay=i2c-gpio,...) on GPIO 13 and 6 the RTC disappears.

The installer asks before adding it, and an update adds it once on an sBitx that has no I2C line yet (keeping a backup, config.txt.jesdr-backup). Earlier jeSDR versions added dtoverlay=i2c-gpio,bus=3,..., which runs the radio but has no clock: an update changes it to the line above, or removes it when an RTC line is there too (backup: config.txt.jesdr-rtc-backup). It takes effect at the next restart. I2C does not need turning on in raspi-config (that is for the Pi's own I2C pins, GPIO 2 and 3): the package loads the i2c-dev module the radio's bus needs. status on the console shows the bus in use (for example i2c: /dev/i2c-2).

At start-up jeSDR sets the Pi's clock from the RTC (unless network time is in already), so the clock is right in the field before GPS or the internet; at shutdown it writes the Pi's clock to the RTC if that session had network time. The clock tool shows the RTC and can set it by hand.
