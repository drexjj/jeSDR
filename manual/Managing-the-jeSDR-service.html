Managing the jeSDR service#

jeSDR runs on the Pi as a system service called jesdr. It starts by itself at every power-up and keeps running whether or not a screen or browser is open. These commands control it from a terminal on the radio or over SSH.

Commands#

WhatCommand
Stop jeSDRsudo systemctl stop jesdr
Start jeSDRsudo systemctl start jesdr
Restart jeSDRsudo systemctl restart jesdr
Don't start at bootsudo systemctl disable jesdr
Start at bootsudo systemctl enable jesdr
Check its statussudo systemctl status jesdr
Start at boot, and start nowsudo systemctl enable --now jesdr
Don't start at boot, and stop nowsudo systemctl disable --now jesdr
Watch its log livesudo journalctl -u jesdr -f
  1. Stop stops jeSDR immediately. The radio un-keys and saves its settings first.
  2. Start starts it again.
  3. Restart stops and starts it. Use it after changing a file by hand, or to recover from a problem.
  4. Disable keeps jeSDR from starting when the Pi boots. It doesn't stop a jeSDR that is running now.
  5. Enable makes jeSDR start when the Pi boots again (the installer enables it).
  6. Status shows whether jeSDR is running, since when, and its last few log lines, including any errors. Press q to leave it.
  7. Enable and start (enable --now) does 5 and 2 in one step.
  8. Disable and stop (disable --now) does 4 and 1 in one step.
  9. Live log shows jeSDR's messages as they happen, for troubleshooting. Press Ctrl+C to leave it. sudo journalctl -u jesdr -b shows everything since the Pi started.

Good to know#

  • The jeSDR desktop shortcut starts the service if it isn't running, even when it is disabled. To keep jeSDR off, don't open the shortcut.
  • After a crash the service restarts by itself within a few seconds. A stop is different: jeSDR stays stopped until you start it again.
  • Settings → Shut down → Stop jeSDR does the same as systemctl stop from the radio's own screen or a browser (see Power, backup, shut down, About).
  • Installing or updating jeSDR restarts the service for you.

  • Editing jeSDR's files by hand (~/jeSDR/data/hw_settings.ini, jesdr.ini): jeSDR reads them only when it starts, and writes them itself (settings when they change; hw_settings.ini after a PA calibration or a reference crystal change), which can overwrite your edits. Stop jeSDR first, edit, then start it:

    sudo systemctl stop jesdr
nano ~/jeSDR/data/hw_settings.ini
sudo systemctl start jesdr
  • Only one radio program at a time. jeSDR needs the audio codec and the GPIO for itself: stop it before running other software that drives the sBitx hardware directly, and start it again afterwards.
