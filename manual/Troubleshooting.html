Troubleshooting#

The screen#

The browser warns about the certificate. The radio makes its own HTTPS certificate. Choose Advanced → Proceed once on each device. After changing the radio's address, delete ~/jeSDR/data/jesdr_cert.pem and jesdr_key.pem and restart to make a new one.

The page doesn't load at all. Check the service on the radio:

sudo systemctl status jesdr
journalctl -u jesdr -f

Nothing else may use the audio codec or the GPIO: remove any other radio program from the desktop autostart.

ERR_TOO_MANY_RETRIES or "This site can't be reached" on some phones or computers, while others work. The device isn't letting the browser reach devices on your home network. Newer Android versions, iPhones, iPads and Macs ask for this permission per app; without it, Chrome is blocked before it reaches the radio, retries, and gives up. Nothing is wrong with the radio. Allow it on the device, then reload the page:

DeviceWhere
AndroidSettings → Apps → Chrome → Permissions → Nearby devices (on some versions Local network) → Allow
iPhone, iPadSettings → Chrome → turn on Local Network (Safari doesn't need it)
Mac (macOS 15 or later)System Settings → Privacy & Security → Local Network → turn on Chrome

Other browsers built on Chrome (Edge, Brave, Opera) have their own switch in the same place. Quick check: if Firefox on the same device opens the radio, it is this permission. If a device still fails, record what Chrome does: open chrome://net-export on it, start logging, load the radio's page, stop, and send the saved file along when you ask for help.

The page says jeSDR is stopped. Someone used Stop jeSDR. Open jeSDR from the radio's desktop or menu, run sudo systemctl start jesdr, or restart the Pi.

The desktop shortcut asks whether to execute or open. Update to the latest version; the package fixes the shortcut.

No sound in the browser on a phone or laptop. Browsers start sound only after a tap: tap the 🔈 button next to PTT. It is hidden on the radio's own screen, which uses the speaker.

Receiving#

The waterfall turns solid or strong signals distort. The receiver is overloaded: lower the IF gain, use the attenuator, or turn on Auto IF gain.

Weak signals are lost in the noise on 10–15 m. Raise the IF gain or use the preamp until the band noise moves the S-meter a little.

Clicks or dropouts in the speaker. These are audio underruns. The console's status shows how many there have been since start, and the log gets one line a minute while they happen (journalctl -u jesdr). Check the Pi isn't hot or short of power (More → Power & battery), and close other heavy programs on the Pi.

A steady tone sits on every signal. Try the birdie shift, or the auto notch for a tone from another station.

No country under calls. Install the country file.

Transmitting#

If the radio won't transmit, the header usually says why:

ShownCauseFix
TX blockedoutside the transmit band plantune inside the band, or check Band plan
SWR tripSWR above the limitfix the antenna, then Clear trip on Transmit and set the drive back
timeout badgethe transmit timeout un-keyedrelease PTT; stop the program holding it
battery flatbattery protectioncharge the battery
—Mic PTT is OFFturn it on in More → Transmit
—the PA calibration is runningwait, or Stop it

Power differs from band to band. Run the PA power calibration.

It keys, but little or no power comes out. See No RF output: the settings to check first, the self-tests that find most faults, and the PA chain step by step.

Changed the Pi's language and lost power? That was a bug in the earlier sBitx software (a different decimal separator broke its calibration). jeSDR always reads its numbers the same way, whatever the Pi's language.

A phone or laptop can't use its microphone. Open the radio over https://<radio>:8443/, not http://, and allow the microphone.

Digital modes#

FT8 decodes nothing, or DT is large. The clock must be right within about a second. Without internet, use a GPS. If decodes show DT around ±0.1 s after a GPS clock set, adjust GPS delay.

WSJT-X can't control the radio. Rig Hamlib NET rigctl, server 127.0.0.1:4532, PTT via CAT; see Connecting other programs.

The JS8 panel says "not connected". JS8Call must be running (Open JS8Call, or the menu) with its API on: Settings → Reporting → API, Enable TCP Server API and Accept TCP Requests, port 2442 (or set JS8Call API, JS8_API, to its port). If it connects and drops every few seconds, another program is using JS8Call's API: raise Max connections in JS8Call. Open JS8Call needs someone logged in to the radio's desktop. If it says JS8Call is not installed, run the installer again and answer yes to JS8Call. JS8Call hears nothing or sends no audio: choose jeSDR Receive and jeSDR Transmit in its Settings → Audio, as for WSJT-X.

WSJT-X (or another program) does not list jeSDR Receive / jeSDR Transmit. status on the console says programs' audio: PipeWire … when jeSDR made them; waiting for the user's PipeWire session means the radio user's PipeWire is not running: log in to the desktop once, or run sudo loginctl enable-linger <user> and reboot. Restart the program after jeSDR started: some list audio devices only when they start.

The desktop's sound goes to the transmitter. jeSDR Transmit became the desktop's default output (no other output on the Pi): pick another output in the volume menu.

No DX cluster spots. Set My call sign, turn Cluster connection ON in More → Station, and check DX cluster spots on the scope in More → Display.

The Pi#

A red Pi badge. The Pi is hot or short of power: check More → Power & battery. Under-voltage can corrupt the SD card; use a supply that holds the voltage while transmitting.

The Pi's CPU is near 100 %. jeSDR itself uses about a quarter of one core; most of the load is what draws and sends the screen. In htop:

  • chromium (the jeSDR window on the Pi's screen): lower More → Display → Waterfall speed on that screen (10 is the default there, 5 halves it again). Open jeSDR with its menu entry or desktop icon, which turns off Chromium's forced accessibility mode. (Green lines in htop are threads of the process above them, not more copies.)
  • wayvnc (only while a VNC viewer is connected): VNC has to encode the moving waterfall all the time. Operate from the other computer's browser instead (https://<radio>:8443/): the Pi then only sends the data, and the other computer draws it.
  • labwc (the desktop) redraws with the windows above it.

No keying, no filter changes, or dead knobs. Look at the start of the log (journalctl -u jesdr -b) for a gpio: line:

Log saysFix
no permission for /dev/gpiochip*sudo usermod -aG gpio <user>, then restart
GPIO8 is in use by the kernel (or 7, 9, 10, 11)SPI is on: comment out dtparam=spi=on in /boot/firmware/config.txt and restart
GPIO4 is in use by the kernela 1-wire overlay (dtoverlay=w1-gpio) holds the PTT pin: remove it
in use by ... a second jesdr?another radio program has the pins; stop it

jeSDR stops at start-up with an i2c: message. The radio's I2C bus (the Si5351, the SWR bridge, the INA260, the RTC) is the kernel's i2c-gpio bus on GPIO 13 and 6; jeSDR no longer bit-bangs those pins and can't run without it.

Log saysFix
the radio's I2C bus was not foundadd dtoverlay=i2c-rtc-gpio,ds1307,i2c_gpio_sda=13,i2c_gpio_scl=6 to /boot/firmware/config.txt and restart the Pi
has no /dev/i2c-N: the i2c-dev module is not loadedsudo modprobe i2c-dev; reinstalling the jeSDR package makes it load at every boot
no permission for /dev/i2c-*sudo usermod -aG i2c <user>, then restart
the Si5351 (0x60) does not answerthe overlay is on other pins, or the bus is wired wrong: check the line above

No RTC since the I2C change (the clock tool says "RTC: none found"). /boot/firmware/config.txt must have exactly one I2C overlay on GPIO 13 and 6, and it must be the clock's: dtoverlay=i2c-rtc-gpio,ds1307,i2c_gpio_sda=13,i2c_gpio_scl=6. A plain dtoverlay=i2c-gpio,bus=3,... line runs the radio but has no clock, and both lines together hide it. Install the current jeSDR package (it fixes the line) or edit it yourself, then restart the Pi. ls /sys/class/rtc should then list a clock whose name says rtc-ds1307.

Starting again. Make a backup, write a fresh SD card image, then restore it.
